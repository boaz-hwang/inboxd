# Decision training mechanisms: source-code audit

This is an implementation audit for borrowing mechanisms, not a recommendation to install Laya or Kev. Source snapshots: [Laya `010bacef`](https://github.com/NandhaKishorM/laya/tree/010bacef009c855ccba814b51f7c8e1d38ab5e3f) and [Kev `557598fc`](https://github.com/jaredpalmer/kev/tree/557598fced1dada75dfbf36ed144dce309ac6ceb), inspected on 2026-09-23. No checkpoints were downloaded or run for this audit.

## What Laya actually computes

Laya formats each question as type/instruction text, option text prefixed by a mask marker, and state text. The state is truncated to a fixed token budget. Its bidirectional encoder and small transformer head produce one logit per option marker, then softmax gives a distribution; this is a **learned decision readout without autoregressive answer generation**, not a free-form LLM boolean. The same forward pass also produces separate action logits. [Sequence construction](https://github.com/NandhaKishorM/laya/blob/010bacef009c855ccba814b51f7c8e1d38ab5e3f/laya/common.py#L49-L86), [model and heads](https://github.com/NandhaKishorM/laya/blob/010bacef009c855ccba814b51f7c8e1d38ab5e3f/laya/common.py#L89-L136).

Its published fine-tuning notebook converts each gold `probabilities` object into a normalized soft target. `choice`/`score` are single categorical distributions; `noul` is `[false, true]`. A missing target is not a third `unknown` class. Each question from one source case becomes a separate training item. [Target creation](https://github.com/NandhaKishorM/laya/blob/010bacef009c855ccba814b51f7c8e1d38ab5e3f/notebooks/laya_finetune_typed_decisions_2xT4_kaggle.ipynb#L108-L145). Padding masks prevent nonexistent option positions from entering the softmax. [Collation](https://github.com/NandhaKishorM/laya/blob/010bacef009c855ccba814b51f7c8e1d38ab5e3f/notebooks/laya_finetune_typed_decisions_2xT4_kaggle.ipynb#L176-L199), [masked logits](https://github.com/NandhaKishorM/laya/blob/010bacef009c855ccba814b51f7c8e1d38ab5e3f/laya/common.py#L114-L117).

The notebook calls the recipe RLCD. The actual objective samples four Gaussian perturbations of the option logits, evaluates their distributions with a log score plus spherical score and, for ordered scores, ranked-probability-score reward, subtracts the group mean reward, and applies a Gaussian log-probability policy-gradient term. It adds **full-weight soft-target cross-entropy** to that term. This is a group-relative REINFORCE-style objective with supervised guidance; the shown code has no PPO clipped surrogate, rollout of generated text, or Brier loss. The `proper_reward` name does not by itself establish calibration on this task, especially with a clipped log reward, finite samples, optimization error, and distribution shift. [Reward](https://github.com/NandhaKishorM/laya/blob/010bacef009c855ccba814b51f7c8e1d38ab5e3f/laya/common.py#L150-L176), [sampling and loss](https://github.com/NandhaKishorM/laya/blob/010bacef009c855ccba814b51f7c8e1d38ab5e3f/notebooks/laya_finetune_typed_decisions_2xT4_kaggle.ipynb#L322-L338).

The action head receives pooled encoder features plus top probability, margin, entropy, and option count. But the published notebook's loss uses `+ 0.0 * act.sum()`: there is **no action-target supervision** in that recipe. Runtime nevertheless returns its softmax as `action.act_probability`. The project README explicitly reports this output as unusable on its labelled check (almost always 1.0; raw-logit AUROC 0.30). It must not be copied as a safe act/defer signal. [Action features/head](https://github.com/NandhaKishorM/laya/blob/010bacef009c855ccba814b51f7c8e1d38ab5e3f/laya/common.py#L119-L136), [zero action loss](https://github.com/NandhaKishorM/laya/blob/010bacef009c855ccba814b51f7c8e1d38ab5e3f/notebooks/laya_finetune_typed_decisions_2xT4_kaggle.ipynb#L334-L338), [runtime output](https://github.com/NandhaKishorM/laya/blob/010bacef009c855ccba814b51f7c8e1d38ab5e3f/laya/agent.py#L381-L424), [README limitation](https://github.com/NandhaKishorM/laya/blob/010bacef009c855ccba814b51f7c8e1d38ab5e3f/README.md#L609-L618).

Post-training, the notebook reserves a random 10% slice of *items* before training and fits one temperature per question type by minimizing soft-target NLL with LBFGS. It clears inherited per-option-count overrides before exporting those three temperatures. Since source cases were expanded into question items **before** the split, questions from one source case may occur in both fit and training sets; a case- or thread-group split is safer for our email task. The notebook separately evaluates the dataset's `test` split, so this is a calibration-split concern, not a claim that its published evaluation has no test data. Runtime clamps extreme shipped temperatures; its own warning says affected confidence should be treated as uncalibrated. [Item split](https://github.com/NandhaKishorM/laya/blob/010bacef009c855ccba814b51f7c8e1d38ab5e3f/notebooks/laya_finetune_typed_decisions_2xT4_kaggle.ipynb#L251-L264), [temperature NLL](https://github.com/NandhaKishorM/laya/blob/010bacef009c855ccba814b51f7c8e1d38ab5e3f/notebooks/laya_finetune_typed_decisions_2xT4_kaggle.ipynb#L201-L218), [fit/export](https://github.com/NandhaKishorM/laya/blob/010bacef009c855ccba814b51f7c8e1d38ab5e3f/notebooks/laya_finetune_typed_decisions_2xT4_kaggle.ipynb#L382-L428), [test load](https://github.com/NandhaKishorM/laya/blob/010bacef009c855ccba814b51f7c8e1d38ab5e3f/notebooks/laya_finetune_typed_decisions_2xT4_kaggle.ipynb#L476-L512), [runtime clamp/warning](https://github.com/NandhaKishorM/laya/blob/010bacef009c855ccba814b51f7c8e1d38ab5e3f/laya/agent.py#L211-L235).

## Kev comparison

Kev uses a causal LM backbone without a vocabulary generation head for decisions, a learned pointer head that scores option representations against a decision representation, and an optional LoRA adapter. This is another example of **learned option scores**, though its backbone and attention scheme differ from Laya's encoder. [Pointer head and backbone](https://github.com/jaredpalmer/kev/blob/557598fced1dada75dfbf36ed144dce309ac6ceb/kev/model.py#L173-L221). Its training code uses soft-target cross-entropy when a distribution is supplied, otherwise hard-label cross-entropy with optional Brier/focal modification and an ordinal cumulative-distribution penalty. The code is not evidence that every shipped checkpoint used every optional loss. [Question loss](https://github.com/jaredpalmer/kev/blob/557598fced1dada75dfbf36ed144dce309ac6ceb/kev/train.py#L37-L57). Its risk/coverage threshold selector maximizes empirical accepted share on the rows supplied to it; deployment needs separate threshold-selection and untouched evaluation partitions. [Threshold functions](https://github.com/jaredpalmer/kev/blob/557598fced1dada75dfbf36ed144dce309ac6ceb/kev/metrics.py#L103-L111), [selection/evaluation](https://github.com/jaredpalmer/kev/blob/557598fced1dada75dfbf36ed144dce309ac6ceb/kev/metrics.py#L149-L164).

## Single mechanism to test in inboxd

The first hypothesis is **replace one free-form decision readout with a trained, option-scoring decision head**, keeping the existing evidence preparation, reply generator, deterministic policy checks, and final checker contract. Compare it with the frozen current 9B behavior on the same Korean/English email threads and drafts before changing production. A shared 9B encoder with a small learned head is an architectural comparator for accuracy but may not save much latency because it still runs the 9B backbone; a separate small encoder can save latency but must prove comparable grounding. They are separate experiments, not an assumed winner.

For a checker pilot, label `supported` and a **separate** error category from independently reviewed source/draft pairs, including sender/recipient reversal, negation, unsupported facts, commitments, and URL evidence. `supported` is a two-class categorical target; add `unknown/needs_review` only if the annotators define and label that state consistently. Reason categories may be multiclass if mutually exclusive or multilabel if failures coexist. Give each output its own validity mask so missing or ambiguous annotations contribute no loss for that output; Laya's option-padding mask is not such an annotation mask. Do not train `supported=true` from the existing checker's approvals or from generated drafts. Keep generation personalization data and checker judgement data distinct to avoid a common learned error.

Start with masked supervised cross-entropy and optionally adjudicated soft labels for genuine annotator disagreement. RLCD's perturbation term is an ablation only after this simpler baseline wins; neither a proper-scoring objective nor temperature scaling prevents confidently wrong role or factual decisions. Split train, temperature/threshold calibration, and final test by email thread/source case, including a fresh held-out role-reversal set. Report false approvals separately from false rejections, reason accuracy, Brier/NLL/ECE, and risk versus coverage with a threshold selected only on calibration data. An action/defer policy can be evaluated from calibrated correctness risk, but an `act_head` needs explicit supervised correctness or downstream-utility targets before its score has meaning. Speed comparison must include preprocessing, encoder/head, and any remaining checker call, at equal functional scope.
