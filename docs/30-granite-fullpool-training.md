# Granite 전체 후보 검토·개인화 학습

작성일: 2026-10-06

상태: **원래 후보 3,086건의 전체 검토, 승인된 1,374건의 한 epoch 학습, 학습 전후 108개 답장의 블라인드 판정 완료. 손실은 감소했으나 실사용 답장 품질은 제한적이다. 운영 모델 활성화 없음.**

사용자의 “기존 3,000건 중 가능한 모든 데이터 활용” 요청에 따라 기존 후보 전체를 다시 처리했다. [27번 문서의 검토 범위 정정](27-historical-reply-training-plan.md#187-2026-10-05-후보-검토-범위-정정과-저장-공간-정리)에서 남아 있던 미검토 후보를 포함한다. [29번 문서](29-granite-reply-model-evaluation.md)는 학습 전 모델의 합성 추론 비교 기록으로 그대로 보존한다.

## 전체 후보와 실제 학습 범위

원래 장부의 서로 다른 3,086개 ID를 기준으로 분할과 검토 목록을 재구성했다. 과거 배치 목록에는 중복과 누락이 있어 전체 모집단으로 사용하지 않았다. 123개 대화방의 동결 원본 기록 11,742건을 모두 해시 일치로 복원했고, 별도로 기존 크기 제한 생략 47건의 메타데이터도 이번 수집과 정확히 일치함을 확인했다. 후보 3,086건 모두 원본·문맥·타깃·입력·출처 키 해시가 기존 장부와 일치한다. 복원 실패나 미판정 후보는 0건이다.

학습 1,374건은 75개 대화방의 실제 자기 답장이며, 원문 해시가 일치하는 기존 승인 447건과 이번 검토의 추가 승인 927건으로 구성한다. 재사용 가능한 기존 승인 부분집합은 처음 453건이었고, 이후 정확한 민감 출처가 겹치는 6건을 제외했다. 기존 판정은 원본·문맥·타깃이 정확히 같을 때만 재사용했고, 추가 문맥으로 해결 가능한 기존 보류와 형식 재검토 대상은 다시 검토했다. 판정 주체는 사용자에게 위임받은 Sol 에이전트이며 `agent_delegated`로 기록한다. 사람의 전수 검수로 표시하지 않는다.

보류한 실제 답장에는 입력에서 확인할 수 없는 완료 상태·일정·장소·개인 선호나, 독립 답장으로 쓰기 어려운 조각이 포함된다. 이를 그럴듯한 타깃으로 새로 작성하거나 문맥 일부를 제거해 승인하지 않았다. 개인정보 제외는 정확히 해당 출처를 공유하는 후보에만 전파했다. 명시적 신원·금융 식별 정보와 접근 권한 링크는 확인된 범주로, 용도가 확인되지 않은 불투명 코드는 보수적 개인정보 보류로 구분한다. 일반 숫자·결제·사업자 언급을 모두 제외하지 않았다. 본문을 가리거나 바꾸어 학습 가능하다고 판정한 사례도 없다.

## 원문 보존과 토큰 경계

운영 생성 프롬프트 전체와 실제 자기 답장을 Granite 공식 토크나이저로 다시 계산했다. `enable_thinking=False`로 렌더링한 생성 접두사를 `add_special_tokens=False`로 인코딩한다. 손실은 실제 assistant 답장과 종료 토큰에만 적용한다.

Granite 템플릿이 답장 끝 공백을 잘라내던 직렬화 문제를 고쳤다. 원문은 그대로 둔 채 생성 접두사 뒤에 실제 답장을 연결해 인코딩하고, 접두사 일치·유일한 마지막 EOS·답장 디코딩의 원문 일치를 확인한다. 제거한 것은 EOS `100257` 뒤의 템플릿 전용 줄바꿈 `198`뿐이다. 이전 경계 실패 44건은 복구했으며, 이 중 한 건은 원문을 보존하면 실제 답장 길이 한도를 넘는 것으로 분류했다. 전체 후보에서 템플릿 공백 손실을 피한 사례는 61건, 최종 학습 승인 중에는 20건이다.

68건의 길이 보류는 전체 프롬프트+실제 답장이 4,096토큰을 넘는 53건과 답장 자체가 운영 생성 한도인 EOS 포함 192토큰을 넘는 15건이다. 65토큰 제한이나 임의의 학습 건수 목표는 사용하지 않는다. 승인된 긴 답장을 짧게 다시 쓰거나 자르지 않는다.

|---|---:|---:|---:|
| 입력 | 2,569 | 3,305.35 | 4,066 |
| 답장+EOS | 19.5 | 58 | 178 |
| 전체 | 2,597 | 3,320.4 | 4,093 |

학습 입력 합계는 3,575,030토큰, 실제 답장+EOS 합계는 33,300토큰이다. 원문과 토큰 ID는 소유자 RAM에만 유지하며 학습기에 로컬 소켓으로 전달한다. 디스크 장부에는 ID·해시·토큰 수·판정 근거 코드만 보존한다. 공개 문서에는 실제 대화 본문·식별 값·개별 출처 키를 넣지 않는다.

별도 Sol 에이전트의 최종 승인 감사는 23개 확인 항목을 모두 통과했다. 원래 3,086개 ID의 상태와 학습 1,374개 ID를 대조하고, RAM 묶음의 실제 학습·검증·test 1,405개 토큰 행을 직접 확인했다. 동결된 학습 순서에 모든 승인 학습 ID가 정확히 한 번 포함됨을 확인했다. 이 감사는 학습 계획과 데이터의 검증이며, 실제 epoch 완주의 증거는 이후 실행 기록으로 확인한다.

## 분할과 평가의 의미

의미 선별 전에 대화방 전체를 평가용으로 예약했다. 처음 예약한 9개 방의 61건은 모두 개인정보 출처 제한으로 사용할 수 없어, 기록된 학습·내보내기·모델 출력 이력이 없는 추가 38개 방 전체를 예약했다. 과거 계획상 TRAIN 예약만 명시적으로 수정했으며, 기존 평가의 출처·타깃·시간 구간·대화방 경계는 유지했다. 추가 방은 개발 과정에서 의미 검토된 적이 있어, 완전히 처음 보는 데이터라고 부르지 않는다. “모델에 사용되지 않음”은 감사한 기존 산출물의 기록 범위에 한정한다.

최종 승인 학습 건과 실제 검증·평가 문맥 사이의 출처 공유, 정규화한 전체 에피소드 동일성, 200자 이상 에피소드의 문자 3-gram Jaccard 0.9 이상 유사도를 검사했다. 학습-검증 41,220쌍, 학습+검증-품질 평가 42,120쌍, 승인된 실제 평가 타깃과의 1,404쌍에서 해당 위반은 모두 0이다. 학습 승인 사이의 완전히 같은 토큰 해시 중복도 0건이다. 이 검사로 의미상 모든 바꿔 말하기까지 탐지했다고 주장하지 않는다.

평가용 59개 사용 가능 후보 문맥에서 원래 자기 답장까지 학습 품질 승인을 받은 타깃은 test 1건뿐이고 primary valid는 0건이다. 따라서 손실 검증은 기존에 관측한 승인 validation 30건을 별도로 사용한다. 이 30건은 원래 3,086건 집계 밖에 있으며, 체크포인트 진단용이다. 독립 품질 시험으로 세지 않는다.

실제 답장 품질 시험은 **문맥만 사용하는 30건**이다. 26건은 판정 가능하고 4건은 애매한 문맥으로 동결했다. 과거 자기 답장이 보류·제외됐더라도 문맥으로 근거 있는 새 답장을 판단할 수 있으면 시험에 포함한다. 과거 타깃은 생성 입력에 전달하지 않는다. 30건 모두 운영 컴파일 preflight가 ready이고, 파이프라인 ABSTAIN은 0건이다. 출력 관측 전에 역할·허용 주장·금지 주장·응답 기준을 동결했다.

## 학습·메모리 시험·학습 후 비교

본학습은 공식 Granite 4.2-3B MLX Q4 기본 모델에서 마지막 8개 층 LoRA rank 8·scale 16·dropout 0, batch 1, Adam 학습률 `2e-5`, seed 42, gradient checkpointing으로 한 epoch 진행했다. 모든 승인 ID 1,374개를 시드로 정한 순서에서 정확히 한 번씩 학습했다. 샘플 수 제한·부분집합 학습·합성 데이터 가중은 없다. 687번째 중간 저장본은 복구·진단용이며, **1,374개를 모두 학습한 최종 저장본만 주 후보**로 사용했다.

최종 규칙으로 재검증한 메모리 pilot은 승인된 실제 긴 입력 3건과 자원 모양만 검사하는 합성 4,096전체/192답장 1건으로 네 번 업데이트했다. 6개 승인 실제 후보와 기존 observed valid 30건의 안전한 pilot 묶음에서 실행했고, 전체 학습은 새 기본 모델과 새 optimizer로 시작한다. pilot 어댑터는 폐기했다. GPU 구간 33.0초, 최대 MLX 메모리 **8.844GB**, OS 메모리 압력 정상, swap 추가 사용 0이었다. 시작 시 이미 사용 중인 swap은 약 1.987GB였으므로 “전체 swap 0”을 뜻하지 않는다. MLX peak와 RSS는 겹치는 별도 측정치라 합산하지 않는다. pilot 이후 데몬 복원까지 확인했다.

학습 때 사용자 요청대로 시뮬레이터·에뮬레이터를 종료하고, RAM 데이터 수신 후 추천 데몬을 일시 정지한다. GPU 자식 프로세스가 종료된 뒤 기존 복원 경로로 데몬을 복원한다. OS 압력 변화·swap 증가·메모리 한도 초과 시 중단한다. pilot의 자원 통과는 본학습 완료나 답장 품질 개선의 증거가 아니다.

학습 후 동결한 실제 문맥 30건과 기존에 본 합성 회귀 24건에서 기본 Granite와 최종 full-epoch 어댑터를 각각 비교했다. temperature 0·비thinking·최대 192토큰·동일 운영 입력을 사용하며 모델별 별도 프로세스로 실행했다. 실제/합성 지표는 따로 집계하고, 역할·사실·응답 필요성의 pass/fail/uncertain과 유용성·말투를 전체 실제 출력에 판정했다. 판정 동결 전 모델 A/B 매핑은 숨겼다. 입력 preflight의 ABSTAIN과 모델 생성은 구분한다. 추가 하이퍼파라미터 탐색이나 운영 활성화는 이 실행에 포함하지 않았다.

### 실제 학습 완주와 자원

승인된 1,374개 ID가 정확히 한 번씩 업데이트됐으며, 최종 1,374번째 저장본을 주 후보로 선택했다. 독립 Sol 감사의 20개 확인 항목도 통과했다. 사용자 요청으로 757건 학습 후 일시 정지했다가 같은 RAM 모델·optimizer에서 이어서 실행했으며, 학습을 처음부터 재시작하지 않았다.

최종 어댑터는 운영 모델 설정에 연결하지 않았으며, 평가가 끝난 뒤 사용자의 정리 요청으로 가중치 파일을 삭제했다. 삭제 전 해시와 파일 크기는 [삭제 기록](/Users/hwang-gyeongchan/.inboxd/reply-model/cleanup/experiment-models-20261006/deletion-receipt.json)에 남겼고, [최종 학습 receipt](/Users/hwang-gyeongchan/.inboxd/reply-model/learning/granite-training-20261006/full-epoch/train/receipt.json)와 어댑터 설정·평가 결과는 보존했다.

자원 기록의 전체 wall-clock 구간은 8,981.60초(149.7분), 사용자 정지는 1,405.13초(23.4분), 정지를 제외한 구간은 **7,576.47초(126.3분)**이다. 별도 `perf_counter` 기록은 7,904.69초로 서로 다른 시계 측정이다. 봉인된 실행 receipt 값은 그대로 보존하며, wall-clock 정지 시간을 `perf_counter`에서 다시 빼서 새 학습 시간을 만들지 않는다.

최대 MLX 메모리는 **8.835GB**, 프로세스 RSS high-water는 **2.463GB**였다. 두 값은 겹치므로 합산하지 않는다. 시작·종료 OS 메모리 압력은 정상이었고, swap 사용량은 약 1.634GB에서 1.423GB로 210.6MB 감소했다. 학습 GPU 프로세스 종료 후 데몬 ready·schema 7 복원을 9.571초에 확인했다. 짝 비교의 GPU 프로세스도 종료됐으며, 평가 후 데몬 복원도 확인했다.

기존 observed valid 30건, 실제 답장+EOS 844토큰의 평균 손실은 **기본 2.75741 → 최종 1.93711(29.75% 감소)**였다. 중간 687번째 저장본의 1.94361은 진단값이다. 손실 검증은 관측된 기존 타깃을 얼마나 잘 예측하는지 보여주며, 새로운 문맥의 답장 안전성이나 유용성을 직접 증명하지 않는다.

### 블라인드 짝 비교 결과

실제 문맥 30쌍의 60개 출력은 데이터 담당 Sol이, 기존 합성 회귀 24쌍의 48개 출력은 별도 Sol이 전수 판정했다. 두 판정 해시를 동결한 뒤 매핑을 열었으며, `run_x`가 최종 학습 모델, `run_y`가 기본 Granite였다. 같은 문맥에서 같은 출력이 나온 합성 사례는 동일하게 판정했다. 실제 문맥에서는 같은 출력 쌍이 없었다. 사람 평가나 공식 승격 기준으로 표시하지 않는다.

유용성·말투는 동결한 1점 사용 불가, 2점 큰 수정 필요, 3점 수정 후 사용 가능, 4점 보낼 수 있음, 5점 문맥과 말투가 잘 맞음의 기준을 썼다. 애매한 실제 문맥 4건은 보이지 않는 첨부 내용을 추론하지 않아야 한다는 제한은 판정할 수 있지만, 일반적인 문맥 정확도 집계에는 합치지 않는다. 판정 가능 실제 26건의 사실 항목 불확실성은 기본 2건·최종 1건이며 모두 다른 항목의 명확한 fail과 함께 발생했다.

실제 판정 가능 26건의 역할 fail은 기본 2건·최종 0건, 사실 fail은 기본 1건·최종 0건, 응답 필요성 fail은 기본 14건·최종 11건이었다. 최종 모델은 인사·감사와 간단한 수락에서 말투가 개선됐지만, 일정 확인·학습 도움·추가 의견 요청에 일반적인 감사나 확인만 답하는 문제가 많았다. 애매한 첨부 문맥에서는 최종 모델이 네 건 모두 확인·감사만 보내고 필요한 설명 요청이나 확인 의도를 제시하지 않았다. 기본 모델의 모델 생성 `<ABSTAIN>` 5건 중 3건은 명시적인 생일 인사나 도움 요청에 대한 불필요한 기권이었다.

합성 회귀에서는 최종 모델의 역할 fail이 6→1건, 사실 fail이 6→4건으로 줄었지만, 세 항목 전부 pass는 7건으로 같았다. 이전 거절 경계를 시험하는 네 사례에서 명확한 거절·동의 뒤집기는 기본 2건·최종 1건이었고, 해당 경계의 불확실성은 기본 1건·최종 3건이었다. 최종 모델에도 수동 결제 거절 뒤 자동 등록을 약속한 오류, 알려지지 않은 참석 가능 여부를 긍정한 오류, 읽지 않은 안내 링크의 허용 규칙을 단정한 오류가 남았다. 짧고 자연스러워졌다는 이유로 이런 답장을 안전하거나 유용하다고 판정하지 않았다.
