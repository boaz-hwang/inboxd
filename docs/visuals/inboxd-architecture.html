01

수신·조회·검색이 같은 저장소로 모입니다

2026-09-22 작업 트리의 구현 기준

계정 전체 경로

관측한 메시지를 로컬에 보관

사용자 조회, 원격 검색, 데몬의 실시간 재조회가 반환한 메시지를 공통 SQLCipher 메시지·FTS 색인에 저장합니다. TUI 없이도 계정 연결과 수신을 유지합니다.

SDK push / 조회→계정 supervisor→관측 commit→구독 이벤트
기존 범위 경로도 유지

관측과 coverage를 구분

기존 message.*·sync.* 경로는 지정된 채팅방·기간의 수집과 근거를 관리합니다. 계정 관측은 같은 DB를 사용하지만 동기화 커서를 전진시키거나 기간 전체의 수집 완료를 선언하지 않습니다.

범위별 워커→core 규칙→공유 SQLCipher
실시간 수신은 구현되어 있습니다. 시작·재연결·주기 sweep은 열지 않은 방도 최근 페이지를 읽지만, 전체 과거 기록을 자동 수집하는 것은 아닙니다. 누락·장기 단절·삭제 근거의 한계는 별도로 표시합니다.

03

검색과 전송의 공통 계약

message.search

local · remote · refresh

local은 암호화 색인, remote는 서비스 조회 후 저장, refresh는 로컬 결과를 먼저 반환하고 작업 ID로 원격 확인을 이어갑니다. TUI와 MCP가 같은 계약을 사용합니다. 출처와 커서를 구분하고 원격 실패 시 로컬 결과를 유지합니다.

message.send

인증 후 한 번 발송

소유자 approver 또는 위임 sender가 capability 검사를 거쳐 발송합니다. 요청 ID를 DB에 먼저 예약해 재시작 뒤 중복도 차단합니다. 기본 MCP agent는 조회 전용이며, 명시적으로 sender 토큰을 제공하면 전송할 수 있습니다.

send.status

접수와 확인을 구분

Sent는 서비스 접수, Verified는 별도 확인입니다. Failed와 결과를 확정하지 못한 Uncertain을 구분합니다. 응답 유실 때는 상태를 조회하며 자동 재발송하지 않습니다. Sent는 상대의 읽음이 아닙니다.

현재 공개 전송 경로는 message.send입니다. 과거의 account.send 및 제안 생성·승인 코드 수령·승인 RPC 설명은 현재 동작에 해당하지 않습니다. 이전 safety 기록 조회·거절과 도메인 코드는 호환 경로로 남아 있습니다.
04

로컬 추천과 안 읽은 대화 처리

Rust가 조회 권한을 제한하고 Python이 추론합니다.

구현된 실행 경로

문맥 판단 → 필요한 기록 조회 → 생성·검증

수신 관측과 방 진입으로 작업을 예약합니다. 최신 실제 발신자가 본인이면 답장 대상이 없어 큐·판단·생성·검증에서 제외합니다. 이전 본인 메시지는 문맥에 남기고, 상대의 후속 메시지가 오면 추천을 재개합니다. Python MLX 상주 워커를 최대 2개 사용해 판단·생성·grounding 검사를 수행하고 Rust가 현재 방의 로컬 history만 조회합니다. 조회는 최대 2 round·3 query이며 버전과 범위를 검사합니다.

수신 / response.open→판단·조회→추천 cache→TUI

설치 기본 모델 경로는 Qwen3.5-9B-4bit입니다. 추론은 로컬 모델 파일과 offline 설정을 사용합니다. 모델 준비 실패 시에도 직접 작성과 전송은 유지합니다.

사용자 조작

Tab 수락 · Enter 전송

준비된 추천은 ghost로 표시하고 Tab으로 초안에 넣습니다. 초안이 없으면 다음 안 읽은 방으로 이동할 수 있습니다. 추천 생성 중에는 대기 안내를 합니다. 방에 들어오면 전체 읽음 처리하며, 보내지 않은 추천은 읽은 뒤 재진입해도 유지합니다. 읽은 방도 최근 대화로 초안을 생성하고, 실패하면 자동 재시도 없이 실패 상태와 원인을 기록합니다. 읽음 상태 변경이나 재진입으로 같은 실패를 재생성하지 않습니다. 빈 기록은 서버에서 조회하며, 끝까지 메시지가 없는 방은 목록에서 제외합니다. Enter로 전송하며 Shift+Tab으로 영역을 이동합니다. Failed·Uncertain에서는 성공처럼 다음 방으로 넘기지 않습니다.

response.open/get/seen/feedback/next는 소유자 전용입니다. 방 진입 시 전체 메시지의 seen과 provider unread 근거를 함께 관리하고, 카카오 서버 읽음은 비동기로 확인·복구합니다.

07

남은 구현과 검증 범위

수신·검색

관측한 범위만 근거로 사용

최근 페이지 sweep은 전체 과거 기록 수집이 아닙니다. 검색 0건·목록 누락을 삭제나 완전한 coverage로 해석하지 않습니다. 실시간 복구와 provider 제한도 구분해 표시합니다.

모델·개인화

현재는 typed LLM baseline

전용 학습 CIM·보정 확률, 다른 대화·메일·파일 connector, trajectory의 자동 학습 데이터 전환과 주기 학습은 남아 있습니다. LoRA는 수동 검토·학습·평가·적용 도구이며 자동 적용하지 않습니다.

검증의 해석

코드 구현과 제품 품질은 별개

이 지도는 커밋되지 않은 변경을 포함한 현재 코드를 설명합니다. 모델 품질·지연은 별도 평가 기록을 따릅니다. 로컬 추론과 메신저 네트워크 통신, 사용자 선택에 따른 외부 MCP 전달도 구분합니다.
